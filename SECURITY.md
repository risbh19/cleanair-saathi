# Security and privacy

Households use a random bearer token stored by their browser. PostgreSQL stores a digest and checks ownership on private reads, changes and deletion. Household deletion cascades to saved plans and carpool offers. Localities are coarse and the profile uses age bands and a single sensitivity flag. Production Compose disables HTTP access logging to avoid retaining locality query strings.

Community totals use the locality captured on the plan. Counts and each modeled impact require five separate contributing households. School-run groups require an explicitly shared random code and show a match flag to participants. Group codes are stored as digests.

The plan and chat routes share a rolling limit of 60 requests per minute per direct network peer per process. The limiter stores only keyed address digests in bounded memory. A reverse proxy can make several clients share a limit. Live AI calls have an additional per-process budget. Configure trusted gateway limits before multi-replica public deployment.

Set server keys through the deployment environment. Source references and numbers rendered by Ask Saathi come from reviewed passages. Model output is restricted to validated IDs. The service worker excludes API traffic. Dependency advisory checks are available under Actions and run weekly on the default branch.
